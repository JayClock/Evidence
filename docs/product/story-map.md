# Evidence 产品故事地图

GitHub Issues/Projects 是 Product Backlog 权威来源。本文件只维护稳定的活动主干和能力地图，不维护具体 Sprint 状态或重复 Issue 内容。

| 顺序 | 用户活动       | 稳定能力                                         |
| ---- | -------------- | ------------------------------------------------ |
| 1    | 进入协作空间   | 用户、工作区、成员和角色                         |
| 2    | 编写逻辑模型   | 逻辑实体、逻辑关系、属性、行为和定义             |
| 3    | 构建关系图     | 图、节点、边、布局和逻辑模型引用                 |
| 4    | 浏览与评审     | 资源浏览、模型解释、错误反馈和变更影响           |
| 5    | AI 辅助建模    | 对话上下文、建模提案、确认与应用                 |
| 6    | 跨运行界面使用 | Web 共享前端、Desktop 壳和一致 REST 语义         |
| 7    | 交付产品增量   | Issue、TQA、示例、模型展开、测试工序、TDD 和学习 |

## 切片原则

- 每个用户故事表达一个角色要解决的问题及价值，而不是技术任务。
- 每个开发迭代只选择一个可验收场景作为最小垂直切片。
- 新候选故事和优先级变化写入 iteration 的 `story-map-delta.md` 与 `backlog-delta.md`，确认后同步 GitHub。
- 已实现能力的事实以产品、领域模型、代码和测试为准，不在本文件维护完成百分比。
