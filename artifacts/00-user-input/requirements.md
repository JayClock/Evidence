# Evidence 工作流种子需求

Evidence 是一个领域建模与证据映射平台。它帮助团队通过定义逻辑实体，并使用节点与边绘制关系图，来建模业务领域。

## 当前产品上下文

- 运行界面：Web SPA、Rust Axum 后端，以及共享同一前端的 Tauri 桌面壳。
- 核心用户：领域建模人员、架构师、分析师，以及需要映射业务证据与关系的团队。
- 核心概念：用户、工作区、成员、图、图节点、图边和逻辑实体。
- 逻辑实体类型：证据、参与者、角色和上下文。
- API 风格：REST 资源，使用 HAL 风格的 `_links`、`_embedded` 和分页。
- 持久化：SeaORM/PostgreSQL，并使用 fake store 契约测试验证领域行为。

## 目标 Evidence 工作流

使用 Evidence 工作流阶段，将新的 Evidence 产品想法转化为可审计工件和真实代码增量：

1. 需求分析 —— 综合输出用户画像、问题陈述和故事地图。
2. 领域建模 —— 细化统一语言、限界上下文、聚合、实体/值对象和领域事件。
3. 架构设计 —— 产出上下文映射、架构风格、技术栈、模块结构、API 契约和数据模型。
4. 迭代计划 —— 创建产品待办、迭代计划、Sprint 1 待办和完成定义。
5. 编码实现 —— 基于选定用户故事修改真实源代码和测试。
6. 评审改进 —— 统一评估工件、代码、测试和完成定义的一致性。

## 仓库约束

- 保留现有 Evidence 架构：React/Vite 前端、Rust Axum 后端、Tauri 桌面壳，以及共享 REST API 语义。
- 保持 `artifacts/` 作为审计日志，`artifacts/gates/` 作为人类审核界面。
- 编码阶段必须修改真实 Evidence 代码和测试，不能只生成 Markdown 说明。
