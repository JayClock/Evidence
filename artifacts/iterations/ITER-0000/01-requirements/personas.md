# 用户画像

本文基于当前 Evidence 项目的产品定位、README、领域模型与现有 API 结构，定义需求阶段的核心用户画像。

## Persona 1：领域建模负责人

| 字段     | 内容                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 角色     | 负责梳理业务领域、统一语言、实体关系和上下文边界的架构师或领域专家                 |
| 目标     | 快速建立可视化领域模型，让团队围绕同一套业务概念协作                               |
| 当前痛点 | 领域知识分散在文档、会议纪要和个人经验中，缺少统一、可追溯的模型表达               |
| 使用场景 | 创建工作区，定义 Evidence、Participant、Role、Context 等逻辑实体，并通过图表达关系 |
| 成功标准 | 能清楚看到实体、关系、上下文边界，并能持续迭代模型                                 |

### 关键需求

- 能在工作区中创建、编辑、删除逻辑实体。
- 能将逻辑实体放到图中形成节点，并连接节点形成关系。
- 能通过实体类型和子类型表达业务语义。
- 能保留实体定义、属性、行为和标签，支撑后续架构与实现讨论。

## Persona 2：业务分析师 / 证据映射分析师

| 字段     | 内容                                                                 |
| -------- | -------------------------------------------------------------------- |
| 角色     | 负责识别业务证据、流程文档、合同、请求、确认等材料之间关系的分析人员 |
| 目标     | 将复杂业务材料整理成结构化证据网络，辅助审计、评审或需求分析         |
| 当前痛点 | 证据材料之间的来源、责任方、上下文和约束关系不清晰                   |
| 使用场景 | 在 Evidence 中维护证据类逻辑实体，并将其与参与者、角色、上下文关联   |
| 成功标准 | 能从图中快速回答“什么证据由谁产生、服务哪个上下文、证明什么业务事实” |

### 关键需求

- 能按 evidence 子类型区分 RFP、proposal、contract、fulfillment request、fulfillment confirmation 等材料。
- 能通过图边表达证据与参与者、角色、上下文之间的关系。
- 能在团队共享的工作区中持续补充证据网络。
- 能通过清晰的实体定义减少歧义。

## Persona 3：产品 / 交付团队成员

| 字段     | 内容                                                           |
| -------- | -------------------------------------------------------------- |
| 角色     | 参与需求澄清、方案评审、交付协作的产品经理、开发人员、测试人员 |
| 目标     | 快速理解业务模型、接口边界和功能范围，降低沟通成本             |
| 当前痛点 | 需求文档、领域模型和实现任务之间缺少连接，团队难以判断变更影响 |
| 使用场景 | 查看工作区、图和逻辑实体，理解当前业务模型并参与评审           |
| 成功标准 | 能通过 Evidence 图和实体说明快速理解领域概念及其关系           |

### 关键需求

- 能浏览默认工作区和已有图。
- 能查看图节点、图边和关联逻辑实体的详细信息。
- 能基于统一语言参与需求和架构讨论。
- 能将模型结果转化为后续开发计划和验收标准。

## Persona 4：桌面本地建模用户

| 字段     | 内容                                                          |
| -------- | ------------------------------------------------------------- |
| 角色     | 希望在本地桌面环境中进行领域建模的个人用户或小团队成员        |
| 目标     | 使用桌面应用进行低摩擦建模，同时复用 Web 前端体验             |
| 当前痛点 | 纯 Web 工具依赖部署环境，本地建模和演示不够方便               |
| 使用场景 | 启动 Tauri 桌面应用，在本地窗口中访问 Evidence 前端和后端能力 |
| 成功标准 | 桌面模式与 Web 模式行为一致，开发和演示流程稳定               |

### 关键需求

- 桌面壳应加载同一套 `apps/web` 前端。
- 桌面开发模式应能稳定启动 Vite 前端和后端服务。
- 桌面构建应能复用 Web 构建产物。
- Web 与 Desktop 不应分裂为两套产品语义。
