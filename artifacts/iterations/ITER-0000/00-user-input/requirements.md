# Evidence 工作流种子需求

Evidence 是一个领域建模与证据映射平台。它帮助团队通过定义逻辑实体，并使用节点与边绘制关系图，来建模业务领域。

## 当前产品上下文

- 运行界面：Web SPA、Rust Axum 后端，以及共享同一前端的 Tauri 桌面壳。
- 核心用户：领域建模人员、架构师、分析师，以及需要映射业务证据与关系的团队。
- 核心概念：用户、工作区、成员、图、图节点、图边和逻辑实体。
- 逻辑实体类型：证据、参与者、角色和上下文。
- API 风格：REST 资源，使用 HAL 风格的 `_links`、`_embedded` 和分页。
- 持久化：SeaORM/PostgreSQL，并使用 fake store 契约测试验证领域行为。

## 目标 Evidence 工作流

使用反馈驱动的 Evidence 工作流，将新的产品想法转化为可审计工件和真实代码增量：

1. 问题框定 —— 产出用户画像、问题陈述、业务上下文、用户旅程和候选故事地图；优先描述角色与价值，而非技术方案。
2. TQA 需求澄清 —— 以单个 `US-xxx` 故事为边界，一次提出一个高价值业务问题，并保存回答和未决问题。
3. 示例规格化与验证 —— 为每个故事写具体 `SC-xxx` Given/When/Then 示例，并确认它可进入建模。
4. 领域建模与模型展开 —— 产出概念字典、半结构化 Mermaid 模型、DDD 工件，并用 Ready 场景验证实体、关系、状态变化和时间顺序。
5. 架构与测试策略 —— 产出功能上下文、Q2 验收测试到 Q1 支撑测试的映射、测试替身选择与可复用测试工序。
6. 垂直切片计划 —— 将一个场景追踪到测试、功能上下文和实现任务。
7. 单场景编码 —— 每次只对选定 `US-xxx / SC-xxx` 执行真实 Red/Green/Refactor。
8. 产品与质量评审 —— 对照验收示例、模型展开、测试策略和完成定义评估结果。
9. 学习与下一轮 —— 记录 Probe/Sense/Respond 反馈，并把下一轮问题框定输入沉淀下来。

## 仓库约束

- 保留现有 Evidence 架构：React/Vite 前端、Rust Axum 后端、Tauri 桌面壳，以及共享 REST API 语义。
- 保持 `artifacts/` 作为审计日志，`artifacts/gates/` 作为人类审核界面。
- 编码阶段必须修改真实 Evidence 代码和测试，不能只生成 Markdown 说明。
