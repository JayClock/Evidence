# 统一语言

本文定义 Evidence 项目在需求、领域建模、架构和实现中应保持一致使用的核心术语。统一语言基于当前项目的 README、AGENTS 说明、Rust domain 聚合、REST API 路由和需求阶段工件。

## 核心业务术语

| 术语     | 英文/代码名   | 定义                                               | 说明                                                                                                |
| -------- | ------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 用户     | User          | 使用 Evidence 的主体，拥有或参与一个或多个工作区。 | 当前默认用户为 `desktop-user`。                                                                     |
| 工作区   | Workspace     | 领域建模与证据映射的协作容器。                     | 包含成员、图和逻辑实体。                                                                            |
| 成员     | Member        | 用户在工作区中的参与关系。                         | 带有角色，例如 owner/member。                                                                       |
| 图       | Diagram       | 用于可视化表达业务概念关系的图模型。               | 由节点和边组成，隶属于工作区。                                                                      |
| 图节点   | DiagramNode   | 图中的可视元素，可引用逻辑实体。                   | 记录节点类型、位置、样式和逻辑实体引用。                                                            |
| 图边     | DiagramEdge   | 图中两个节点之间的关系。                           | 记录 source、target、relation type 和 label。                                                       |
| 逻辑实体 | LogicalEntity | 被建模的业务概念。                                 | 类型包括 Evidence、Participant、Role、Context。                                                     |
| 证据     | Evidence      | 业务中可证明事实、请求、承诺或履约状态的材料。     | 子类型包括 rfp、proposal、contract、fulfillment_request、fulfillment_confirmation、other_evidence。 |
| 参与者   | Participant   | 在业务关系中参与活动的人、组织或事物。             | 子类型包括 party、thing。                                                                           |
| 角色     | Role          | 参与者、系统、上下文或证据在业务中承担的职责。     | 子类型包括 party、domain、3rd system、context、evidence。                                           |
| 上下文   | Context       | 一组有一致业务语义和边界的领域范围。               | 当前子类型为 bounded_context。                                                                      |
| 属性     | Attribute     | 逻辑实体的结构化特征。                             | 用于描述实体可被记录或比较的信息。                                                                  |
| 行为     | Behavior      | 逻辑实体在业务中的能力或动作。                     | 用于表达领域概念可执行或可触发的动作。                                                              |
| 标签     | Tag           | 用于分类、检索或辅助说明的轻量标记。               | 不应替代核心类型和子类型。                                                                          |
| 引用     | Ref           | 领域对象之间的类型化引用。                         | 用于表达跨实体关系而不泄漏持久化细节。                                                              |
| 集合     | HasMany       | 聚合下的子集合访问边界。                           | 提供 `find_all`、`find_by_identity`、`size` 等行为。                                                |
| 实体     | Entity        | 拥有 identity 和 description 的领域对象。          | 当前项目的核心 domain trait。                                                                       |

## API 语言

| 术语              | 定义                                  | 约定                                         |
| ----------------- | ------------------------------------- | -------------------------------------------- |
| HAL Resource      | 带 `_links` 的资源响应。              | 资源应包含 self、collection 和相关资源链接。 |
| HAL Collection    | 带 `_embedded` 和 `page` 的集合响应。 | 列表接口需要分页元数据。                     |
| self link         | 指向当前资源的链接。                  | 所有主要资源都应提供。                       |
| collection link   | 指向所属集合的链接。                  | 便于客户端返回列表。                         |
| default-user link | 根资源指向默认用户的入口。            | 支持桌面/本地快速进入。                      |
| page/pageSize     | 分页查询参数。                        | 集合接口统一使用。                           |

## 错误语言

| 术语       | 定义                               | 使用场景                                                       |
| ---------- | ---------------------------------- | -------------------------------------------------------------- |
| NotFound   | 目标资源不存在。                   | 查询、更新、删除不存在的用户、工作区、图、节点、边或逻辑实体。 |
| Validation | 输入不满足业务规则或数据结构要求。 | 缺失必填字段、类型非法、引用非法。                             |
| Conflict   | 请求与当前状态冲突。               | 重复成员、重复资源或违反唯一性约束。                           |
| Internal   | 系统内部错误。                     | 数据库错误或未预期失败，需映射为稳定响应。                     |

## 一致性规则

- “工作区”是协作与模型隔离的主边界，不应把图或逻辑实体直接挂在用户下面。
- “图”表达可视关系，“逻辑实体”表达业务概念，两者不能混用。
- “图节点”可以引用“逻辑实体”，但节点自身主要承担布局、样式和图内呈现职责。
- “图边”表达节点之间的图内关系，关系类型和 label 应尽量使用统一语言。
- “证据”是逻辑实体的一类，不等同于所有文档附件；它必须能证明某个业务事实或状态。
- Web 与 Desktop 是运行界面差异，不是两个不同产品或两个不同领域模型。
- fake store 与 PostgreSQL store 必须遵循同一领域契约。

## 建议术语使用

| 推荐说法   | 避免说法           | 原因                                      |
| ---------- | ------------------ | ----------------------------------------- |
| 逻辑实体   | 白板节点、普通卡片 | 强调这是可被建模和引用的业务概念。        |
| 图节点     | 逻辑实体本身       | 节点是图上的呈现，逻辑实体是业务概念。    |
| 工作区成员 | 项目用户           | 成员表达用户与工作区之间的角色关系。      |
| 证据映射   | 文档管理           | Evidence 的目标是关系建模，不是泛文档库。 |
| 运行界面   | 产品版本           | Web/Desktop 共享同一产品语义。            |
